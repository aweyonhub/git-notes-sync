# Code Review 归档

## 文件命名格式

```
doc/review/<branch-name>-<commit-id>.md
```

- `<branch-name>`：当前分支名（短名，不含 `origin/` 前缀），如 `b016`
- `<commit-id>`：被 review 的 HEAD 短哈希（7 位），如 `ab898ea`
- 示例：`b016-ab898ea.md`

## 文件内容结构

每份 review 文档按以下顺序组织：

1. **标题行**：`# Code Review: <branch> @ <commit-id>`
2. **元信息块**（引用块）：review 范围、分支、改动规模、核心内容的一句话概述
3. **优先级说明**（引用块）：P0–P3 定义（P0 = 阻断，上线前必须修；P1 = 重要缺陷，上线前应修；P2 = 低优先级，建议修；P3 = 极低，可选打磨）
4. **问题清单**：一张汇总大表，每行一个问题，列含序号、优先级、问题、必要性说明、改动方案、用户确认内容（需确认写具体内容，不需要写"无"）、改动量、性能影响、是否推荐、位置、是否完成
5. **汇总结论**：按 P0–P3 分组列出必修项 / 建议补测项 / 后续项 / 建议执行顺序
